# 投诉分类与路由

## 分类表

| 类型 | 典型表述 | 路由 |
|------|----------|------|
| 周报/月报生成 | 生成周报、生成本月报、生成8月月报、出月度报告 | 主智能体直接调用 generate_dify_report（query：周报/月报/N月月报），不委派 |
| 重投原因深度分析 | 为什么重投、重投原因分析、原因归类查询、超时或未解决的重投单、1~9类归因 | **直接委派 analytics-agent**（skill：chongtou-root-cause-analysis，表 chongtou_root_cause_detail）。不要先查知识库 |
| 数据分析 | 用户明确要求：各地市投诉量、超时统计、方案库聚合、按时间/地市下钻、查业务库 | 直接委派 analytics-agent。知识库无结果后的可选方案，须用户下一句同意后再委派 |
| 个人投诉梳理 | 资费争议、网络质量、业务办理、服务态度等个人诉求（非建单、非 mock 查账/网管） | 可委派 ticket-agent 做诉求梳理与建议；或主智能体直接安抚说明。当前**无**建单/用户信息/账单/网管实时工具 |
| 知识库问答 / 指标询问 | 指标定义、口径释义、及时率怎么算、政策规则、名词解释、流程规范；笼统「最近重投情况如何」（非原因归因、非生成周报/月报） | 本轮只调用 search_dify_kb，不委派、不先读文件。未指定日期时**只答最近一期**；开篇简洁标明数据时段（勿堆文件名）；无匹配则回复「暂无此结果」，询问是否委派数据分析专员，并结束本轮。同一轮不调用 task |

## 规则
1. **重投原因深度分析优先于知识库**：命中「为什么重投 / 原因归类 / 超时未解决重投」等 → 直接 analytics-agent；
2. 其余知识库问答和指标口径：先查知识库；无结果不自动委派；
3. 一个诉求涉及多个类型时，按上表分别处理，最后汇总；
4. 缺少手机号、月份、位置等关键信息时，先向用户追问，不要猜；
5. 出现「工信部」「315」「起诉」「曝光」等字眼，标记为升级投诉；
6. 不要假装已创建工单、已查账单或已查网管（相关测试工具已下线）；
7. **数据诚实**：涉及统计/重投分析时，只转述子智能体基于库表的结果；时间口径以重投表 **`"派单时间"`**（或其他表对应真实时间字段）为准；禁止主智能体自行补「2024 年至今」等未查证区间、改数字或改文案圆场。若用户质疑口径/占比，应再委派 analytics-agent 按同粒度规则重查，不要主智能体口头改数。
